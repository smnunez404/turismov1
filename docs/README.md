# Documentación del proyecto

## Jerarquía documental

1. [Auditoría integral del brief de juego social](./18-auditoria-brief-juego-social.md): estado vigente de cumplimiento, evidencia y límites del prototipo local.
2. [Evolución visual del feedback](./15-evolucion-visual-feedback.md): contrato visual vigente y matriz de los 15 apartados.
3. [Arquitectura del avatar explorador personalizable](./17-arquitectura-avatar-explorador-personalizable.md): contrato vigente de estado, render progresivo, encuadres y fallback completo.
4. [Handoff de generación de assets](./16-handoff-generacion-assets.md): instrucciones para producir e integrar avatar modular, tucán y escenarios; su sección 14 gobierna nombres y rutas del avatar.
5. [Auditoría y registro de implementación](./14-auditoria-coherencia-implementacion.md): cierre técnico anterior y contexto de coherencia.
6. [Bitácora de decisiones](./04-bitacora-decisiones.md): decisiones de alcance vigentes.
7. [Especificaciones](./02-specs/): comportamiento implementado por pantalla o capacidad.
8. [Documento maestro](./00-documento-maestro.md): baseline histórica; las decisiones y auditorías posteriores prevalecen cuando exista una diferencia.

Para avatar: el documento 17 gobierna arquitectura; la sección 14 del documento 16 gobierna producción; SPEC-32 gobierna comportamiento funcional.

## Regla de oro

Si algo no está documentado, no está acordado. Todo cambio de alcance se registra en la bitácora. Ninguna pantalla demo debe interpretarse como una cuenta, publicación, envío, beneficio, premio o interacción real con terceras personas.
